> 📌 예시 글이에요. 개념 글은 이 순서(한 줄 요약 → 비유 → 정확한 설명 → 해보기 → 정리)를 따라 쓰면 편해요.

## 한 줄로 말하면

Git은 **내 파일의 '저장 포인트'를 차곡차곡 남겨 주는 도구**예요.

## 비유로 이해하기: 게임 세이브

게임에서 보스를 만나기 전에 저장해 두죠? 지더라도 저장한 곳부터 다시 하면 돼요. Git도 똑같아요.

- 숙제를 하다가 "여기까지 잘 됐다!" 싶으면 저장 포인트를 하나 만들어요. 이걸 **커밋**(commit)이라고 불러요.
- 나중에 뭔가 망가지면, 잘 되던 저장 포인트로 돌아갈 수 있어요.
- 저장 포인트마다 "무엇을 바꿨는지" 짧은 메모를 남겨요. 그래서 기록을 보면 언제 무엇을 했는지 한눈에 보여요.

## 그냥 파일을 복사해 두면 안 되나요?

`숙제_최종.hwp`, `숙제_진짜최종.hwp`, `숙제_진짜진짜최종.hwp`…
이렇게 하면 어떤 게 최신인지, 무엇이 바뀌었는지 금방 헷갈려요.
Git을 쓰면 파일은 하나만 두고, 바뀐 기록은 Git이 뒤에서 대신 정리해 줘요.

## 조금 더 정확하게

| 쉬운 말          | 진짜 이름            | 뜻                                                       |
| ---------------- | -------------------- | -------------------------------------------------------- |
| 저장 포인트      | 커밋 (commit)        | 그 순간 파일들의 모습을 사진 찍듯 남긴 것                |
| 저장 포인트 모음 | 저장소 (repository)  | 커밋들이 모여 있는 곳                                    |
| 저장할 것 고르기 | 스테이징 (`git add`) | 이번 저장 포인트에 넣을 파일을 골라 담는 단계            |
| 인터넷 사물함    | GitHub               | 저장소를 인터넷에 올려 두는 곳. 다른 컴퓨터에서도 볼 수 있어요 |

## 직접 해보기

```bash
# 이 폴더에서 Git 시작하기
git init

# 바뀐 파일을 전부 이번 저장에 담기
git add .

# 메모와 함께 저장 포인트 만들기
git commit -m "첫 저장"

# 지금까지 만든 저장 포인트 보기
git log
```

## 오늘의 정리

- Git = 저장 포인트(커밋)를 남기는 도구
- 망가져도 예전 저장 포인트로 돌아갈 수 있다
- GitHub = 그 저장 포인트들을 인터넷에 보관하는 곳
