# 100일 공부 기록 블로그

하루 1시간 공부한 내용을 글로 쌓는 개인 블로그예요.

- **사이트 주소:** https://vextige.github.io/studyblog/
- **비용:** 0원 (공개 저장소 + GitHub Pages 무료)
- **구조:** 로그인·서버·데이터베이스가 없는 **정적 사이트**예요. 미리 만들어 둔 웹페이지 파일을 그대로 보여 주는 사이트라는 뜻이에요.
- **만든 도구:** [Astro](https://astro.build) (마크다운 글을 웹페이지로 바꿔 주는 도구), GitHub Pages (무료 호스팅), GitHub Actions (자동 배포)

---

## 어디에 뭐가 있나요?

| 위치 | 내용 |
| --- | --- |
| `src/content/posts/` | ⭐ **글이 들어가는 곳.** `.md` 파일 하나가 글 하나예요 |
| `templates/new-post.md` | 새 글 템플릿 (사이트에는 안 올라가요) |
| `src/pages/about.md` | 소개 페이지 |
| `src/consts.ts` | 블로그 이름, 한 줄 소개, 태그 목록 |
| `src/styles/global.css` | 디자인(색상, 글자 크기 등) |
| `src/pages/`, `src/layouts/`, `src/components/` | 페이지 틀. 글만 쓸 거라면 건드리지 않아도 돼요 |
| `.github/workflows/deploy.yml` | 자동 배포 설정 |
| `astro.config.mjs` | 사이트 주소 설정 |

> ✏️ **직접 고칠 곳:** VSCode에서 `Ctrl + Shift + F`로 `✏️`를 검색하면 모두 나와요. (소개 페이지의 닉네임, 공부 중인 것, 목표 등)

## 1. 새 글 쓰는 법

### ① 템플릿 복사하기

`templates/new-post.md`를 복사해서 `src/content/posts/` 폴더에 붙여 넣어요.

### ② 파일 이름 바꾸기

`day-004.md`처럼 **`day-세자리숫자.md`** 로 바꿔요.

- 파일 이름이 곧 글 주소가 돼요. `day-004.md` → `.../studyblog/posts/day-004/`
- 영어 소문자, 숫자, `-`만 쓰는 게 안전해요. (한글이나 띄어쓰기는 피하기)
- 하루에 글을 두 개 쓰면 `day-004-2.md`처럼 붙이면 돼요.

### ③ 맨 위 정보 채우기

파일 맨 위 `---`와 `---` 사이에 글 정보를 적어요.

```yaml
---
title: "변수가 뭔지 알게 된 날"
date: 2026-10-26
day: 4
tags: ["기록"]
description: "목록에 보일 한 줄 요약"
---
```

| 항목 | 뜻 | 규칙 |
| --- | --- | --- |
| `title` | 제목 | 따옴표 안에 적기 |
| `date` | 쓴 날짜 | `연-월-일` 형식 (예: `2026-10-26`) |
| `day` | 며칠째인지 | 1~100 숫자. 홈 화면 "Day N / 100"이 가장 큰 숫자를 따라가요 |
| `tags` | 글 종류 | `기록`, `개념`, `독서` 중에서 고르기. 여러 개면 `["기록", "개념"]` |
| `description` | 한 줄 요약 | 없어도 돼요 (줄째로 지우기) |

### ④ 본문 쓰기

글 종류마다 이렇게 쓰면 편해요.

| 태그 | 형식 | 참고할 예시 |
| --- | --- | --- |
| `기록` | 오늘 배운 것 / 어려웠던 점 / 내일 할 것 (템플릿 그대로) | `day-001.md` |
| `개념` | 한 줄 요약 → 비유 → 정확한 설명 → 직접 해보기 → 정리 ("초등학생도 이해하는 설명") | `day-002.md` |
| `독서` | 읽은 것 → 핵심 3줄 → 내 생각 | `day-003.md` |

**마크다운 기본 문법**

```markdown
## 큰 제목
### 작은 제목

**굵게**, `코드`, [링크 글자](https://example.com)

- 목록
- 목록

1. 번호 목록
2. 번호 목록

> 인용(강조 상자)
```

코드 블록은 백틱 세 개(```` ``` ````)로 감싸고 언어 이름을 붙이면 색이 입혀져요. (예: ` ```python `)

### ⑤ 미리 보고 → 올리기

아래 [2. 미리 보는 법](#2-내-컴퓨터에서-미리-보는-법)으로 확인하고, [3. 배포](#3-배포되는-과정-인터넷에-올리기)로 올리면 끝이에요.

### 자주 하는 실수

| 증상 | 해결 |
| --- | --- |
| 화면이나 터미널에 빨간 오류가 떠요 | 오류 메시지에 **파일 이름과 칸 이름**(예: `tags`)이 나와요. 그 칸의 형식을 확인하세요 |
| 태그 오류 | `기록` / `개념` / `독서` 중 하나인지, 철자가 맞는지 확인 |
| 날짜 오류 | `2026-10-26`처럼 `-`로 이어 쓰기 (`2026.10.26` ❌) |
| `**굵게**`가 안 돼요 | 한국어에서 `**커밋(commit)**이라고`처럼 괄호 뒤에 조사가 바로 붙으면 안 돼요. `**커밋**(commit)이라고`처럼 바꾸세요 |
| 예시 글을 지우고 싶어요 | `src/content/posts/`의 `day-001.md` ~ `day-003.md`를 지우면 돼요 |

## 2. 내 컴퓨터에서 미리 보는 법

인터넷에 올리기 전에 내 컴퓨터에서 먼저 확인할 수 있어요. VSCode에서 **터미널**(메뉴 → 터미널 → 새 터미널)을 열고 입력해요.

**처음 한 번만** (라이브러리 설치. `node_modules` 폴더가 없을 때만)

```bash
npm install
```

**미리보기 켜기**

```bash
npm run dev
```

브라우저에서 👉 **http://localhost:4321/studyblog/** 를 열어요.

- 주소 끝에 `/studyblog/`를 꼭 붙여야 해요. (실제 사이트 주소와 똑같이 맞춰 두었어요)
- 글을 고치고 **저장하면 화면이 자동으로 바뀌어요.**
- 끌 때는 터미널에서 **`Ctrl + C`**

> 💡 `localhost`는 "내 컴퓨터"라는 뜻이에요. 이 주소는 나만 볼 수 있고, 인터넷에는 아직 안 올라간 상태예요.

**(선택) 실제 배포와 똑같이 확인하기**

```bash
npm run build     # 배포용 파일을 dist 폴더에 만들기 (GitHub Actions가 하는 일과 같아요)
npm run preview   # 만든 파일로 미리보기
```

`npm run build`에서 오류가 안 나면, 인터넷에 올려도 배포가 성공해요.

> ℹ️ 이 컴퓨터에는 Node.js 24가 설치되어 있어요. 다른 컴퓨터에서 작업하려면 Node.js 22.23 이상이 필요해요.

## 3. 배포되는 과정 (인터넷에 올리기)

### 한눈에 보기

```
① 내 컴퓨터에서 글 작성 (.md 파일)
        │  git push  ← 내가 하는 건 여기까지!
        ▼
② GitHub 저장소에 파일이 올라감
        │  자동으로 시작
        ▼
③ GitHub Actions가 사이트를 빌드 (.md → 웹페이지 HTML)
        │  자동
        ▼
④ GitHub Pages가 인터넷에 공개 → https://vextige.github.io/studyblog/
```

**글을 올리기만 하면 나머지는 자동이에요.** 보통 1~2분 뒤에 사이트에 반영돼요.

### 처음 한 번만: git push 로그인 연결

이 컴퓨터에는 GitHub CLI(`gh`)로 이미 로그인되어 있어요. 아래 명령을 한 번 실행하면 `git push`도 그 로그인을 쓰게 돼요. 비밀번호를 파일에 저장하지 않아요.

```bash
gh auth setup-git
```

### 매번: 글 올리기

```bash
git add .                          # 바뀐 파일을 모두 이번 저장에 담기
git commit -m "Day 4 글 추가"       # 메모와 함께 저장 포인트 만들기
git push                           # GitHub에 올리기 → 자동 배포 시작
```

> 💡 명령어 대신 VSCode 왼쪽의 **소스 제어**(가지 모양 아이콘)에서 메시지를 쓰고 **커밋** → **변경 내용 동기화**를 눌러도 똑같아요.

### 배포가 잘 됐는지 확인하기

1. https://github.com/vextige/studyblog/actions 에 들어가요.
2. 맨 위 "사이트 배포" 옆에 표시가 떠요.
   - 🟡 노란 점: 진행 중
   - ✅ 초록 체크: 성공. 사이트를 새로고침해 보세요.
   - ❌ 빨간 X: 실패. 눌러서 빨간 줄의 오류 메시지를 확인하세요. 대부분 글 맨 위 정보의 형식 문제예요. 고쳐서 다시 push하면 돼요.

> 🛟 배포가 실패해도 **기존 사이트는 그대로** 있어요. 빌드에 성공해야만 사이트가 바뀌어요.

## 안전과 개인정보

- **공개 저장소예요.** 글뿐 아니라 저장소의 모든 파일을 누구나 볼 수 있어요. 실명, 학교, 연락처 같은 개인정보는 신중하게 적어 주세요.
- **비밀번호·토큰·API 키는 절대 파일에 넣지 마세요.** 자동 배포는 GitHub가 그때그때 주는 임시 권한만 써요.
- **커밋 이메일:** 이 프로젝트에는 개인 이메일 대신 GitHub 공개용 주소(`...@users.noreply.github.com`)가 설정되어 있어요. 커밋 기록에 개인 이메일이 남지 않아요.
- 저장소 이름을 바꾸면 사이트 주소도 바뀌어요. 이때는 `astro.config.mjs`의 `base: '/studyblog'`도 새 이름으로 바꿔야 해요.
